# Ma trận API Mobile và Backend

Rà soát FE `3c01db0`, BE `0bc2b38` ngày 24/11/2026. Đường dẫn ghi theo controller, cần ghép với context deploy. Một số hàng nhóm các endpoint cùng nghiệp vụ. Controller nằm trong `CASMS_Backend/src/main/java/com/casms`. Priority ở hàng KEEP thể hiện ưu tiên nghiệm thu.

Transport Mobile đọc `ApiResponse.data` hoặc JSON raw. UUID, enum và các trường nullable quan trọng được kiểm ở adapter tương ứng. Ví dụ Booking dùng `Confirmed`, Cruise dùng `IN_PROGRESS` và Itinerary dùng `ACTIVE`, và giờ/cabin có thể chưa tồn tại. HTTP 401 làm hết phiên hiện tại, 403 giữ phiên. SSE và tài sản 3D có response stream. Xem [báo cáo kiểm thử](CASMS_MOBILE_PHASE_0_TEST_REPORT.md) để phân biệt adapter đã nối và luồng đã chạy qua Backend.

## Ghi chú DTO và validation

- `PassengerItineraryResponse` trả booking/passenger/cruise UUID riêng và danh sách `cruiseSchedule`, `registeredActivities`. Ngày dùng LocalDate. Giờ dự kiến/thực tế là Instant và có thể vắng, cần giữ trạng thái thiếu giờ. Cabin được kéo từ chi tiết booking.
- `CheckinResponse` là projection có `bookingPassengerId`, `checkinStatus`, contact khẩn, mốc started/completed/boarding-ready và lý do chặn. Contact và thời điểm chưa phát sinh có thể trống. Field `passengerId` trên đường dẫn mang giá trị BookingPassenger UUID.
- `PosDtos.SaleInput` yêu cầu service, bookingPassenger, account UUID và idempotency key, giới hạn quantity 1; scheduleId tùy chọn. `Sale` trả số tiền BigDecimal, thông tin charge/reversal phụ thuộc trạng thái. `Statement` bọc Budget và History. FE kiểm schema cùng đối chiếu account ID trong adapter.
- `CancellationController.Intake` yêu cầu scenario và reason tối đa 1.000 ký tự, issueId có thể vắng. POST bắt buộc header Idempotency-Key. Decision có revision không âm. V132 tạo persistence cho case.
- `NotificationResponse` chứa UUID, loại, title, content và các Instant. `readAt` vắng biểu thị chưa đọc. SSE là transport sự kiện riêng. Khi reconnect, dùng REST list/count đồng bộ lại.
- Claim gồm code và expiresAt, preview trả tên và BookingPassenger UUID, confirm/lookup thêm confirmedAt. Cả ba thao tác POS dùng header X-POS-Session. Body preview có code tối đa 43 ký tự; confirm/lookup cardIdentifier tối đa 64.
